# Open Field Studio + АОСР / КС-2 — рабочий MVP

**Версия:** MVP 1; ветка `feature/ru-aosr-ks2-prototype`. **Статус:** локальная браузерная версия работает и проходит автоматическую интеграционную проверку. Печатные документы — ЧЕРНОВИКИ до утверждения реальной формы заказчиком.

## Как запустить на Mac

```bash
cd '/Users/test/Documents/work/yura/Documents/Source-Repositories/Open-Field-Studio'
npm ci
npm run dev
```

Открыть **http://127.0.0.1:3042/**, выбрать **RU** и вкладку **«АОСР · КС-2»**. Остановить сервер: `Ctrl+C` в терминале.

## Пять шагов, чтобы получить свои документы

1. На вкладке **«Проект»** указать объект, адрес и заказчика, на вкладке **«АОСР · КС-2»** — подрядчика, проектировщика, шифр проекта и участников.
2. Ввести до 15 актов: название работы, даты, фактический объём/единицу, исполнительную схему, документы качества и ID позиции КС-2. Пустые строки не проверяются как оформленные акты.
3. Загрузить позиции КС-2 в **CSV** либо **XLSX**. Для XLSX указать лист, строку заголовков и четыре колонки. Программа покажет пример строк и перечень отбрасываемых записей до подтверждения. Для отдельного **исходного АОСР .xls** предусмотрена кнопка «Импорт исходного АОСР (.xls)» (листы `Шапка` / `Табл`). Файл КС-2 при этом загружается отдельно.
4. Просмотреть раздел **«Результаты технической сверки»**. При совпадении объёмов и единиц будет «Количество совпадает»; ошибки и недостающие подтверждения выводятся отдельно. Несколько АОСР могут ссылаться на одну позицию КС-2.
5. Скачать **«Экспорт АОСР в Excel (.xlsx)»**, **«Печатные черновики (HTML)»** или JSON. Книга Excel содержит 20 листов, включая 15 форм актов, общий ввод, реквизиты, позиции КС-2 и результат сверки. Экспортированную книгу можно импортировать обратно для продолжения работы. Для PDF печатать HTML/Excel в PDF.

## Контроль, перевод и данные

- Русский каталог локализации содержит **414 из 414** оригинальных ключей; параметрические шаблоны и переменные `{0}`, `{1}` прошли проверку. Непереводимые названия платформ и стандартов (BAG, IFC, NEN) сохранены.
- Экспериментальный модуль проверяет обязательные поля, порядок дат, повтор номеров актов, ссылки на КС-2, единицы и разницу объёмов. Это **не проверка юридического соответствия КС-2 или АОСР**, не верификация фактических работ и не аттестация электронных подписей.
- Исходный аналитический скрипт отключён; автоматическая проверка обновлений не запускается без добровольной настройки. Самостоятельно включаемые пользователем сторонние интеграции имеют отдельные правила передачи данных.
- В репозитории только **вымышленные тестовые сведения**. Пример: [Демо_АОСР_КС2.xlsx](examples/Демо_АОСР_КС2.xlsx), данные [pto-demo.json](../public/pto-demo.json), [скриншот русской вкладки](screenshots/07-pto-ru.png).

## Команды проверки

```bash
npm test                         # 16 тестов: расчёты, перевод, Excel roundtrip
npm run lint                     # ESLint
npm run build                    # производственная сборка Vite
npx playwright install chromium  # одноразовая установка браузера для тестирования
npm run test:e2e                 # 1 интеграционный Chromium-сценарий
npm audit --omit=dev             # проверка известных уязвимостей прод-зависимостей
```

Тест в браузере проверяет русский язык, пример актов, числовую сверку, редактирование, скачивание и загрузку Excel, импорт КС-2 XLSX с маппингом, экспорт JSON/HTML и сохранение состояния после перезагрузки. В GitHub CI добавлена отдельная job для браузерного теста.

## Ограничения перед официальной сдачей документов

- Нужно сверить распечатку с **утверждённым заказчиком шаблоном АОСР** и применимыми нормативами. Текущий Excel/HTML — технические черновики, даже если они проходят арифметическую проверку.
- Нужны согласование связей АОСР↔позиции КС-2, проверка ОЖР, фактических схем, действительности сертификатов, подписантов и их полномочий.
- Импорт старого **.xls** работает для известной структуры АОСР `Шапка`/`Табл`; произвольный XLS с другой схемой ячеек не поддерживается без адаптера.
- Сборка нативного Tauri-дистрибутива для macOS **не проверена**: на рабочем Mac не обнаружены Rust/cargo. Браузерная версия локально работает; для десктопного выпуска требуется отдельная компиляция и проверка разрешений.
- Источник Open Field Studio упоминает CC BY-SA 4.0; до промышленного распространения необходимо отдельно изучить права на используемые части исходного проекта.
