# Русский интерфейс и АОСР из исходного макета — итерация 2

## Что реализовано

**Язык интерфейса:** для чистой установки русского форка выбран русский по умолчанию; остальные языки можно выбрать в меню. 429 ключей общего каталога (414 прежних + 15 новых) имеют русские значения. Дополнительно в исходном HTML на систему перевода переведены 178 прежних статических надписей. Для 15 комплектов встроенных проверок добавлен русский словарь на 273 вопроса, названия шаблонов и варианты ответов. При просмотре вопросов язык отображения меняется, но исходные сохранённые значения вариантов ответа и пользовательские записи не изменяются. Иностранные обозначения нормативов NEN/Wkb/BAG/IFC оставлены собственными названиями; они **не становятся российскими нормативами**.

**Акты:** при импорте старого АОСР `.xls` с листами `Шапка` и `Табл` программа сохраняет структуру первого 43-колоночного акта **локально**. При экспорте формируется 15 листов `Акт_01`…`Акт_15`, лист `Постоянные_поля` с общей редакцией реквизитов, `Реквизиты`, `Ввод_работ`, а также вкладки КС-2 и контроля. Для круглого цикла импорта/экспорта исходная сетка хранится в **очень скрытом** листе `Исходная_сетка` и не передаётся на сервер.

- Вид работ, даты, материалы и номера актов связаны с одной строкой `Ввод_работ`.
- Если отдельное название исполнительной схемы не задано, оно **формулой** повторяет актуальное наименование работ.
- Предлагаемый номер схемы `ИС-01`, `ИС-02` и далее вычисляется автоматически, но явно помечается **«не подтверждён»**. Подтверждённый номер вводится вручную и не подменяется подсказкой.
- Общие части исходной формы (наименование и адрес, участники, основания полномочий, подписи, ссылки на нормы) сохраняются из **файла, загруженного самим пользователем**. Их можно исправить на общем листе, изменения отражаются во всех актах.
- КС-2 по-прежнему загружается отдельно; совпадение цифр не является нормативным заключением.

## Важное ограничение исходного формата XLS

Читатель BIFF8 `xls-reader` переносит **тексты и позиции 43 колонок**, но не возвращает оригинальные настройки объединений, стилей, точные ширины и границы печатных страниц. Поэтому выходные акты имеют **восстановленную структуру**, а не гарантированную визуальную копию исходного 109-строчного документа. В каждый лист добавлена пометка **«ЧЕРНОВИК»**. Для официальной сдачи необходимо сверить распечатку с утверждённым образцом и вручную проверить подписание, уполномоченных лиц и реквизиты. Не выдавать этот экспорт за готовую юридически значимую исполнительную документацию.

Если исходный АОСР не загружен, работает прежний упрощённый 20-листовый генератор. С исходным макетом создаются 22 листа, включая два вспомогательных листа для структуры/реквизитов.

## Тесты и конфиденциальность

`npm test`: 21 тест (включая воспроизводимость структуры и сохранение пользовательских подписей); `npm run test:e2e`: 2 браузерных сценария, включая живой русский чек-лист и документооборот АОСР; `npm run build`, `npm run lint`. Оригинальный реальный файл и созданные из него отчёты остаются только в приватном `yura/docs` на Mac; в GitHub отправляется только код и синтетические тесты.

## Как пользоваться

1. Открыть русский Open Field Studio → вкладка **«АОСР · КС-2»**.
2. Выбрать **«Импорт исходного АОСР (.xls)»**; подтвердить импорт.
3. Исправить нужные поля на общей форме и в таблице 10–15 работ. Номера схем проверить отдельно.
4. Скачать XLSX и открыть `Постоянные_поля` для общих реквизитов, `Ввод_работ` для изменяемых полей, `Акт_01`…`Акт_15` для печати.
5. Сверить с исходным макетом и применимыми требованиями, подписать только после инженерного контроля.
