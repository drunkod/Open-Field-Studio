# Модуль «АОСР / КС-2» — первая рабочая итерация
Ветка: `feature/ru-aosr-ks2-prototype`. Основание: интервью инженера ПТО и исходная структура Excel (общие реквизиты + таблица работ + 10–15 актов). Рабочие реальные данные в форк **не включены**.
## Быстрый старт
```bash
npm ci
npm run dev
# открыть URL Vite в браузере, в меню языка выбрать RU, затем вкладку «АОСР / КС-2»
npm test
npm run build
npm run lint
```
Приложение хранит введённые сведения локально вместе с общим проектом Open Field Studio; обычный «Сохранить проект (JSON)» также включает `ptoWorkspace`. Для явного экспорта модуля есть «Сохранить JSON» на новой вкладке.
## Что действительно работает сейчас
- Русский перевод **всех 414 ключей исходного интерфейса** (термины/сокращения BAG, NEN, IFC сохранены), плюс русская вкладка АОСР.
- Новая вкладка с 5 общими реквизитами, использованием основных сведений об объекте из вкладки «Проект» и 15 строками для актов; незаполненные строки не считаются актами.
- Изменяемые поля: номер и вид работы, даты, схема, документы материалов, фактический объём/единица, ссылка на позицию КС-2.
- Ввод позиций КС-2 вручную либо импортом CSV или **XLSX с выбором листа и явным сопоставлением заголовка/колонок**. Неподходящие строки перечисляются перед подтверждением. XLS старого формата предварительно конвертируется в XLSX.
- Группировка нескольких актов, ссылающихся на одну строку КС-2; точное суммирование десятичных значений, обнаружение расхождения, неверных единиц, дат, отсутствующих документов и дублированных номеров.
- Печатный **HTML-черновик** и экспорт **XLSX на 20 листах**: Реквизиты, Ввод_работ, КС-2, Сверка, Акт_01…Акт_15 и Инструкция. Актовые листы связаны формулами с общим вводом; возможен повторный импорт книги этого прототипа. Сохранение в PDF — через печать в браузере или Excel.
- Встроенный **полностью вымышленный** учебный набор (`public/pto-demo.json`) с примером совпадения двух актов с одной позицией КС-2 и отдельным расхождением.
## Чего нет (не выдавать за готовую функциональность)
Прямого импорта устаревших КС-2 XLS (нужно конвертировать), сверки с реальным ОЖР, проверки действительности сертификатов, реальных исполнительных схем, количества по факту, нормоконтроля АОСР №344/пр, квалифицированной подписи, утверждённого макета печати 1:1 и выпуска подписанных актов. Имеется только **сопоставление введённых пользователем значений**, не юридическое подтверждение соответствия КС-2 или законодательству.
## Архитектура
- `src/pto/domain.mjs`: независимая модель, проверки дат/количеств/связей, чтение CSV, безопасный HTML-экспорт.
- `src/pto/ui.mjs`: отдельная новая вкладка и формы, минимальное вмешательство в исходный 4000-строчный `public/app.js`.
- `src/locales/ru.json`: русские подписи (остальные исходные локали сохранены).
- `tests/pto-domain.test.mjs`: тесты домена через Node.js Test Runner.
- `docs/DEVELOPMENT_PLAN_RU.md`: анализ реиспользуемых репозиториев и дорожная карта.
## Проверки перед промышленным внедрением
1. Пользователь должен сопоставить позицию КС-2 с конкретными актами и подписанными измерениями; агрегированная сметная строка может охватывать другие виды работ.
2. Инженер/сметчик подтверждают единицы и объёмы. Любое совпадение объёмов обозначено «количество совпадает», не «акт соответствует».
3. Согласовать у заказчика текст и печатный шаблон АОСР; тестировать перенос между страницами, приложения, все подписи.
4. Для реальных файлов использовать только локальные/разрешённые хранилища, не публиковать чувствительные реквизиты в GitHub.
5. Перед распространением определить условия лицензии исходного Open Field Studio (README заявляет CC BY-SA 4.0, standalone LICENSE в исходном клоне не обнаружен).
## Следующий этап
Сначала добавить безопасный импорт `.xlsx` для КС-2 с визуальным сопоставлением колонок и конкретным утверждённым XLSX шаблоном АОСР, используя идеи `excel-template-filler`. Затем — связи на ОЖР, справочник сертификатов, архив с проверкой человеком.

## MVP: проверенное окружение и запуск

- **Локальный запуск:** Node.js 22+; `npm ci`; `npm run dev`; в браузере `http://127.0.0.1:3042`; выбрать RU и вкладку «АОСР · КС-2».
- **Проверка:** `npm test` (включая модель, XLSX roundtrip и перевод); `npm run build`; `npm run lint`; `npx playwright install chromium` и `npm run test:e2e` (браузерный тест сам запускает Vite).
- **Учебный пример без реквизитов реального объекта:** `public/pto-demo.json` и `docs/examples/Демо_АОСР_КС2.xlsx`.
- **Конфиденциальность:** исходный внешний аналитический скрипт отключён, автоматическая проверка обновлений отключена (можно добровольно включить `ofs_allow_update_check=1`). Пользовательские интеграции отправляют данные только при их явном использовании; не включайте их для конфиденциальных материалов без разрешения.
- **Доказательство проверки:** исходники тестов — `tests/pto-domain.test.mjs`, `tests/pto-xlsx.test.mjs`, `tests/pto-i18n.test.mjs` и `tests/e2e-pto.spec.mjs`; браузерный снимок `docs/screenshots/07-pto-ru.png`.

Отказ от юридической аттестации не означает отсутствия полезной проверки: MVP действительно контролирует даты, дубли номеров, отсутствующие сведения, единицы измерения и арифметическое сопоставление количеств.
