# План разработки Open Field Studio → АОСР + сверка КС-2
Дата: 28 октября 2026. Ветка: `feature/ru-aosr-ks2-prototype`, форк: https://github.com/drunkod/Open-Field-Studio.
Исходный проект: https://github.com/OpenAEC-Foundation/Open-Field-Studio (в README лицензия CC BY-SA 4.0; до выпуска ПО и переподключения чужого кода проверить условия использования каждой части).
## Что попросил сотрудник и чего не попросил
Инженер ПТО (кровли, 10–15 видов работ на объекте) хочет один набор реквизитов, одну таблицу изменяемых полей (работа, даты, исполнительная схема, документы материалов) и 15 автоматически заполняемых актов. Даты уточняются по журналу, объёмы — по схемам и сметному отделу/КС-2. Подготовку схем он назвал творческой работой и не просил автоматизировать.
Форма КС-2 — акт о приёмке выполненных работ, постановление Госкомстата 11.11.1999 №100. КС-2 и акт освидетельствования скрытых работ — разные документы. Сверка возможна по сопоставленным позициям, описаниям, единицам и количествам, но НЕ доказывает нормативную законность, подписание, фактическое выполнение или полное совпадение.
Источник для определения КС-2: https://www.consultant.ru/document/cons_doc_LAW_26273/
## Что у нас уже есть в исходном Open Field Studio
Встроенные инспекции/чек-листы, handover, чертежи/фото, локальное хранилище и i18next, React/Vite/Tauri оболочка. UI основной части реализован в `public/app.js` (~4000 строк); для минимального риска новую область делаем **отдельным модулем**, не переписывая существующее хранение/маршрутизацию.

## Дорожная карта, проверки и статусы
### Этап 0 — структура и безопасный форк
Форк GitHub + локальная feature-ветка; изучить зависимости и сохранить исходный функционал. В план не переносить реальные реквизиты объектов/организаций из приватного образца. **Статус: выполнено.**
### Этап 1 — отдельная доменная модель и алгоритм сверки
Поля: общие реквизиты проекта, 15 строк АОСР, связь с номерами схем, видами материалов/документов, даты, единицы и измеренные объёмы, КС-2 позиции (с отдельными ID).
Сверять *группы* АОСР по ссылке на одну позицию КС-2, потому что одна позиция может покрывать несколько актов. Диагностика: ошибки дат, обязательные поля, дубль номера, отсутствие позиции, несовпадение единиц, расхождение объёма; при отсутствии данных — «не подтверждено», а не «соответствует».
Результат: независимый ES-модуль и automated tests, даты/числа с явной локалью, не использовать JS float без допуска. **Статус: реализуется в этой сессии.**
### Этап 2 — UI / российская локаль / сохранение
Новая вкладка АОСР и КС-2, правка всех 15 строк, импорт CSV позиций КС-2, общий реквизитный блок, русские подписи и язык RU в меню; сохранение на устройстве; безопасный экспорт/импорт JSON. Только синтетические примеры.
Результат: работающий браузерный модуль без загрузки документов в облако. **Статус: реализуется в этой сессии.**
### Этап 3 — акт / проверка / экспорт
Отдельные печатные АОСР на основе введённых данных, маркировка «ЧЕРНОВИК», список предупреждений и реестр связи с КС-2. Сначала HTML/печать/JSON, затем точный XLSX по исходному утверждённому макету.
**Статус: HTML и JSON реализуются сейчас, XLSX/печать 1:1 — следующий этап.**
### Этап 4 — интеграция реального Excel
Адаптер старого `.xls` и источника КС-2 `.xlsx` с явным сопоставлением колонок и юридически подтверждённой печатной формой. Перечень видов работ, сертификатов, журнал, ссылки на реальные схемы; импорт делается локально, без отправки. Тест на копии данных, с согласием на использование. **Статус: запланирован.**
### Этап 5 — качество, approvals, BIM
Подписание согласно действующему российскому праву только после экспертизы; интеграция исполнителей, версий, OCR и PDF приложений; позже IFR/IFC/карта схем. **Статус: запланирован.**
## Критерии приемки текущей итерации
- Отдельная вкладка не ломает существующие инспекции и handover.
- Общие реквизиты заполняются один раз, 15 актов — редактируемые отдельные записи.
- Проверка обнаруживает: неверные даты; дубликат номера; несвязанную КС-2; несовпадение единиц; расхождение количеств; отсутствие данных.
- Для одного КС-2 ID несколько АОСР агрегируются, чтобы не выдавать ложное расхождение.
- Экспорт показывает статус проверки и не говорит о юридическом соответствии, опасный HTML экранируется.
- Автоматические тесты домена; Vite build и npm lint; по возможности headless UI smoke тест.
- Файлы заказчика и исходный XLS не публикуются в форке.
