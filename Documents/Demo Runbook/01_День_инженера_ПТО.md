# Сценарий 01. Рабочий день инженера ПТО (кровля)

**Персона:** инженер ПТО. **Объект:** «Учебный объект „Кровля-А“», № DEMO-PTO-2026-01. **Участники:** «Пример-Заказчик» и «Пример-Кровля» — вымышленные. **Время сценария:** последовательность действий, не измеренная производительность.

## Утро: сверка проекта и 15 актов

1. Открыть вкладку **«Проект»**. Проверить название, шифр объекта, заказчика, адрес, участников и ответственных. Для учебного примера использовать только вымышленные данные. Скриншот: [01 — Проект](screenshots/01-project.png). Для российских объектов можно открыть официальный ФИАС/ГАР по отдельной ссылке [31](screenshots/31-project-fias-ru.png); адрес не сверяется автоматически.
2. Перейти в **«АОСР · КС-2»**. Нажать **«Загрузить вымышленный пример»** или ввести сведения вручную. На странице есть общие реквизиты и **15 актов АОСР**. По умолчанию показаны карточки **«Краткий ввод — 3 группы»**: [34 — открытый акт](screenshots/34-pto-quick-act.png). Для объёмов и связи с КС-2 переключиться на **«Все графы — подробный режим»**: [33 — все столбцы](screenshots/33-pto-full-acts.png). На экране показаны три заполненные учебные работы, остальные 12 строк остаются свободными. [11 — раздел ПТО](screenshots/11-pto.png), [12 — список актов](screenshots/12-pto-acts.png).
3. Просмотреть данные первого акта: **1.0 — Гидроизоляция кровли, зона А (демо)**, 01–02.10.2026, **5 м²**, проектная схема **ИС-01**, условный сертификат DEMO-001, позиция КС2-01. Для второго — **1.1, зона Б**, 03–04.10.2026 и **7,5 м²**; для третьего — **1.2, утеплитель, зона А**, 04–05.10.2026 и **22 м²**. Эти строки служат только учебным примером.

## Днём: ОЖР, документы и объёмы

4. Раскрыть **«Импорт записей ОЖР из CSV / XLSX»**. Выбрать [Демо_ОЖР_для_импорта.csv](examples/Демо_ОЖР_для_импорта.csv). Убедиться, что колонка номера акта соответствует «№ акта», дата — «Дата выполнения», описание — «Описание работ», ссылка — «Страница журнала». Нажать **«Проверить строки ОЖР»**. [16 — точный экран предварительного просмотра](screenshots/16-pto-ojr-preview.png).
5. Увидеть **2 подходящие строки** по акту 1.0 и **1 отклонённую** по отсутствующему акту 1.99. Нажать «Импортировать проверенные записи» только после просмотра. Галочка предложения дат нужна только для пустых полей: уже введённые даты не заменяются. Само приложение НЕ проверяет подлинность бумажного ОЖР.
6. В блоке **«Локальные файлы исполнительной документации»** выбрать акт 1.0 и тип «Паспорт материала», приложить реальный файл только после согласия организации и проверки его источника. Скриншот показывает **синтетический PDF**, сохранённый локально, с SHA-256: [15 — вложения](screenshots/15-pto-evidence.png). Один паспорт можно связать с несколькими актами без повторной физической копии.
7. В регистрах ОЖР / качества / исполнительных схем вписать номера страниц журнала, реквизиты материала, номер схемы, редакцию и имя файла; проверить таблицу замечаний: [17 — реестры](screenshots/17-pto-document-register.png). Отсутствующая ссылка означает лишь отсутствие записи в нашем инструменте, не доказанное отсутствие оригинала.
8. Проверить позиции КС-2: соответствие объёмов по схеме и в сметном акте, единицу измерения и общий код при связи нескольких АОСР с одной позицией. [13 — КС-2](screenshots/13-pto-ks2.png), [14 — технические предупреждения](screenshots/14-pto-validation.png). Значения из КС-2 проверяются по оригиналу у сметного отдела, не утверждаются программой.

## Конец дня: подготовка сдаваемого комплекта

9. Нажать **«Комплект актов для печати (.xlsx)»** для отдельных черновиков АОСР или **«Собрать комплект ИД с приложениями (.zip)»** для архива с черновиками, регистрами, замечаниями и вложениями. Подтвердить предупреждение и сохранить файл в согласованную локальную папку. [18 — кнопки рабочего раздела](screenshots/18-pto-main-after-import.png).
10. Открыть АОСР в Excel, проверить **фактическую утверждённую форму**, шапку, подписи, нормативы, схемы, паспорта, оригинальные даты и объёмы. Распечатать предусмотренное договором количество экземпляров (инженер в интервью называл 2–3). Согласовать с проектировщиком/заказчиком там, где это необходимо.
11. Сохранить рабочую копию проекта JSON и **отдельно резервную копию файлов-вложений**. ZIP-архив сдачи и резервная копия вложений — разные функции. Завершить день с перечнем нерешённых замечаний.

## Что входит в демонстрацию, а что нет

**Показано в действующем интерфейсе:** общие реквизиты, 15 строк актов, импорт ОЖР, КС-2, регистры, SHA-256, кнопки выгрузки. **Не доказано:** юридическая пригодность печатного образца конкретному заказчику, действительность сертификата, соответствие оригинальному ОЖР и обязательным XML/XSD, квалифицированные подписи, реальная экономия времени. Эти проверки проводятся только в пилоте с инженером.
